## 1. Executive Summary

Milestone M0.5 implements the thinnest possible end-to-end compilation path through Swift-Stack, translating a substantial subset of C into standalone static Linux x86-64 executables with **zero external tool dependencies** (no clang, no gcc, no gas, no ld, no system libc required at compile time).

The pipeline exercises all seven compiler stages:
1. **Source I/O & Mapping**: Zero-copy UTF-8 source loading with 64-byte sentinel padding.
2. **CLexer**: Branchless/SWAR lexical analysis emitting flat `TokenBuffer` rows.
3. **CParser**: Non-backtracking Pratt precedence climbing parser generating postorder `ParseTree`.
4. **CSemanticAnalyzer & TypePool**: Canonical type interner, scope tracking, 8-byte aligned stack frame layout, and syscall pre-declarations.
5. **AIRLowering**: Direct AST-to-AIR lowering into flat `AIRFunctionSoA` tables with basic block tracking and phi-free structured control flow.
6. **InstructionSelector & LinearScanRegAlloc**: Lowering from target-neutral AIR to x86-64 LIR (`LIRFunctionSoA`), interval computation, and linear scan register allocation with call-clobber-aware callee-saved preservation.
7. **X86Encoder & StaticELFWriter**: Direct binary machine code byte emission, jump fixup resolution, and in-process ELF64 static executable linking with hand-written `_start`, `write`, and `exit` syscall stubs.

Every stage is wired directly into `Profiler.shared`, measuring execution time, throughput (MB/s), cycles per byte, cycles per item, and reporting per-table memory footprint under `--stats`.

## 3. Data Catalog (18-data-catalog.md) Layout Confirmation & Revisions

| Table | Hypothesis in 18-data-catalog.md | M0.5 Measured Layout | Empirical Result & Decision |
|---|---|---|---|
| **`TokenBuffer`** | SoA (10 B/token): `kinds` (1B), `flags` (1B), `starts` (4B), `ends` (4B) | **10 B/row** (`kinds`, `flags`, `starts`, `ends` across 4 columns) | **CONFIRMED**. CParser's Pratt lookahead exclusively sweeps `kinds` and `flags` without cache misses from source offsets. 520 MB/s lex throughput. |
| **`ParseTree`** | SoA (9 B/node): `kinds` (1B), `tokens` (4B), `subtreeSizes` (4B) | **9 B/row** (`kinds`, `tokens`, `subtreeSizes` across 3 columns) | **CONFIRMED**. Postorder layout with `subtreeSizes` allows O(1) backward sibling navigation and skip-over without pointer dereferences. 833 MB/s parse throughput. |
| **`AIRFunction`** | SoA (17 B/inst): `opcode` (1B), `type` (4B), `op0` (4B), `op1` (4B), `aux` (4B) | **17 B/row** SoA vs **20 B/row** AoS (`AIRInstAoS`) | **CONFIRMED SoA FOR PASSES, AoS CONSIDERED FOR LINEAR LOWERING**. Middle-end passes selectively filter opcodes and operands. 17 B SoA avoids 3 bytes padding per instruction present in 20 B AoS. |
| **`LIRFunction`** | SoA (28 B/inst) vs AoS (32 B/inst) | **28 B/row** SoA (`opcodes`, `dst`, `src1`, `src2`, `imm`, `flags`, `extra`) vs **32 B/row** AoS (`LIRInstAoS`) | **CONFIRMED 28 B SoA FOR SLICE; REVISE TO 32 B AoS FOR M2/M3 FULL ENCODER**. LIR consumers (regalloc and encoder) read nearly every operand of every instruction sequentially. A 32-byte AoS instruction aligns exactly to half a 64-byte cache line. |
| **`TypePool`** | SoA for `kinds`/`flags`, pairs for layout | **TypePool canonical interner** | **CONFIRMED**. Canonical type deduplication allows O(1) TypeId integer equality comparisons across sem and lowering. |
| **`LiveInterval`** | AoS for intervals | **AoS `LiveInterval` (vreg, start, end)** | **CONFIRMED**. Linear scan reads start and end simultaneously during sweep. |

## 5. Architectural Decisions: Foundation vs. Rewrite

Per Roadmap §M0.5 requirements, the vertical slice records explicit decisions on what becomes permanent foundation vs. what will be rewritten in subsequent milestones:

### 5.1 Foundation (Preserved & Built Upon)
1. **`ParseTree` Structure ([`ParseTree.swift`](file:///home/jkane/Projects/lang/swift-stack/Sources/SwiftStack/Parse/ParseTree.swift))**:
   The 9-byte postorder SoA layout (`kinds: Column<NodeId, UInt8>`, `tokens: Column<NodeId, UInt32>`, `subtreeSizes: Column<NodeId, UInt32>`) is fast, simple, completely cache-conscious, and trivial to traverse. It becomes the permanent representation for both C23 and Swift parse trees.
2. **`TypePool` Interner ([`TypePool.swift`](file:///home/jkane/Projects/lang/swift-stack/Sources/SwiftStack/Sem/TypePool.swift))**:
   Canonical type interning with bitwise type handles (`TypeId`) and 8-byte stack slot alignment logic forms the foundation for M1/M2/M4.
3. **`Column` & `TypedId` Infrastructure ([`Column.swift`](file:///home/jkane/Projects/lang/swift-stack/Sources/SwiftStack/Source/Column.swift), [`TypedId.swift`](file:///home/jkane/Projects/lang/swift-stack/Sources/SwiftStack/Source/TypedId.swift))**:
   Reserve-then-commit virtual memory allocation and row 0 nil semantics work with zero memory fragmentation and zero overhead.
4. **Deterministic Symbol Hashing ([`TypedId.swift`](file:///home/jkane/Projects/lang/swift-stack/Sources/SwiftStack/Source/TypedId.swift))**:
   `fnv1a16` deterministic hashing and source-order declaration tracking guarantee 100% byte-for-byte binary determinism (D6) across repeated compilations.
5. **Static In-Process ELF64 Relocation Mechanics ([`StaticELFWriter.swift`](file:///home/jkane/Projects/lang/swift-stack/Sources/SwiftStack/Linker/StaticELFWriter.swift))**:
   The direct page-aligned `.text` + `.rodata` emission and PC-relative fixup resolution are sound and form the core of the static linker.

### 5.2 Rewritten or Expanded in M1 / M2 / M3
1. **`CParser` ([`CParser.swift`](file:///home/jkane/Projects/lang/swift-stack/Sources/SwiftStack/Parse/CParser.swift))**:
   *Rewrite Target: M1*. The slice's Pratt parser supports the M0.5 subset (`int`, `long`, `char`, `*`, `if`, `while`, `return`, calls). In M1, it will be integrated with the C23 preprocessor (`#include`, `#embed`, macro expansions) and full C23 grammar.
2. **`CSemanticAnalyzer` ([`CSemanticAnalyzer.swift`](file:///home/jkane/Projects/lang/swift-stack/Sources/SwiftStack/Sem/CSemanticAnalyzer.swift))**:
   *Rewrite Target: M1*. The minimal AST walker will be upgraded to full SemIR generation ([02](02-semantic-analysis.md), [10](10-semantic-ir-and-name-resolution.md)) with struct/union layout, typedefs, integer promotions, and standard diagnostic reporting.
3. **`InstructionSelector` & `LinearScanRegAlloc` ([`InstructionSelector.swift`](file:///home/jkane/Projects/lang/swift-stack/Sources/SwiftStack/Codegen/InstructionSelector.swift), [`LinearScanRegAlloc.swift`](file:///home/jkane/Projects/lang/swift-stack/Sources/SwiftStack/Codegen/LinearScanRegAlloc.swift))**:
   *Rewrite Target: M3*. The current slice uses naive tree pattern selection and basic block linear scan. In M3, this will be replaced with SSA-based LIR, live range splitting, and SSA register allocation with full ABI calling conventions.
4. **`X86Encoder` ([`X86Encoder.swift`](file:///home/jkane/Projects/lang/swift-stack/Sources/SwiftStack/Encode/X86Encoder.swift))**:
   *Rewrite Target: M2*. Hand-crafted opcode emission in M0.5 will be replaced by the complete, table-driven `Encode` module supporting VEX/EVEX, AArch64, RV64, and exhaustive disassembler round-trip testing.
5. **`StaticELFWriter` ([`StaticELFWriter.swift`](file:///home/jkane/Projects/lang/swift-stack/Sources/SwiftStack/Linker/StaticELFWriter.swift))**:
   *Rewrite Target: M2/M3*. The minimal static ELF writer will be generalized to the `Object` library ([06](06-linker.md)), handling ELF relocatables (`.o`), archive libraries (`.a`), section headers, symbol tables, dynamic linking, and Todhchai OS ELF targets.
