### 2.2 Scale Corpus (`Benchmarks/corpora/c-synth/synth_50k.c`)
- **Lines:** 48,154 non-blank/comment lines
- **Source Bytes:** 1,454,005 bytes (1.45 MB)
- **Status:** **Incompatible with M0.5 slice.** The synthetic corpus exercises full C23 features (`typedef`, `struct`, `uint32_t`, `int64_t`, `->`, `++`, `[[nodiscard]]`), whereas M0.5 implements a subset parser (`int`, `long`, `char`, `*`, `if`, `while`, `return`, calls).
- **Correction:** Prior report numbers (833 MB/s parse, 992 MB/s sema) measured an error-recovery skip loop that emitted no function bodies or AIR instructions, and exited 0. With error gating enforced, `swift-stack` now correctly rejects this file with a parse error diagnostic and non-zero exit code (1). Valid throughput benchmarking on a full-scale corpus is deferred to M1 when full C23 grammar and typedefs are implemented.

## 5. Table Layout Hypotheses (18-data-catalog.md) Status

1. **`TokenBuffer`**: 10 bytes/row SoA (`kinds`, `flags`, `starts`, `ends`). Confirmed functional and compact in M0/M0.5.
2. **`ParseTree`**: 9 bytes/row SoA (`kinds: UInt8`, `tokens: UInt32`, `subtreeSizes: UInt32`). Confirmed functional with O(1) postorder traversal.
3. **`AIRFunction`**: 17 bytes/row SoA vs 20 bytes/row AoS (`AIRInstAoS`). **UNVERIFIED HYPOTHESIS**: AoS layout is defined in code but was never benchmarked against SoA. Performance delta remains an open hypothesis.
4. **`LIRFunction`**: 28 bytes/row SoA vs 32 bytes/row AoS (`LIRInstAoS`). **UNVERIFIED HYPOTHESIS**: AoS layout is defined in code but was never benchmarked against SoA. Performance delta remains an open hypothesis.
5. **D6 Determinism**: Verified byte-for-byte identical output across repeated runs. Initial `fnv1a16` hash collisions (`fcel`/`fkba`) and Swift Dictionary non-deterministic iteration order were eliminated by adopting deterministic sequential callee mapping and source-declaration-order iteration.
